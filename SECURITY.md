# Security

This private prototype controls the signed-in user's Paseo installation. A shared call link is not a guest account: its holder can read workspace information, send questions and authorized work requests to agents through the same queued messaging path using the owner's resources and billing. Do not publish links or share them with untrusted recipients. There is no per-user workspace isolation. If the owner enables voice title renames in laptop settings, all paired callers can also request display-title changes. The default is off; branch/directory changes and direct workspace creation are not exposed. The gate is enforced server-side and cannot be enabled through an LLM tool argument.

Call links are single-use and expire after one minute. Browser pairing lasts 12 hours. The service validates Host/origin, uses HttpOnly SameSite cookies and isolates call/job ownership. The anonymous Cloudflare tunnel exposes the companion page, not the Paseo daemon or OpenAI key. Localhost calls avoid the tunnel.

Key settings, provider billing and administrative diagnostics additionally require the local control credential and a localhost Host header. The credential is passed in the settings-link fragment and removed from browser history immediately; it is not persisted in browser storage. Reopen the settings link after reloading or restarting the service. These controls are not provided to the voice model. No browser endpoint returns saved keys. Settings changes affect new calls; existing calls retain their established provider session.

Keys and runtime state are stored outside the checkout in `~/.paseo/voice/`, with directory mode 0700 and files 0600. These are permission-protected local files, not encrypted storage. Existing environment/key-file configuration remains supported. An optional Admin API key has broader billing privileges; use a dedicated project filter where practical. Provider billing totals can cover other applications and are not added to the plugin estimate.

No raw audio is recorded locally. Recent transcript handoff is kept in tab sessionStorage for up to 12 hours; End call clears it. Message text/replies are retained in the private outbox for up to 24 hours. Diagnostic files contain only allow-listed event metadata, timings and classifications, hashed message correlation IDs, script revisions and ephemeral per-page random IDs (no device identifier or raw user agent); usage files retain token counts/cost estimates without transcript text. Provider data policies still apply.

Report vulnerabilities privately to the Trailblaze repository owners. Never include live credentials, launch links, cookies or unsanitized conversation dumps in an issue or commit. Rotate any exposed credentials.

During automatic network recovery, microphone capture can stay active for up to two minutes to preserve the audio route; speech during an outage is not recorded or replayed. End call or closing the page cancels recovery and stops capture. Recovery expiry also stops capture. If the system ends microphone capture, automatic recovery stops and an explicit Resume conversation tap is required to acquire it again; temporary mute/interruption alone does not end the call. Reconnection hands over bounded text context and does not replay workspace mutations.

Agent messaging no longer imposes a read-only instruction on questions or routes them through a separate tool. This does not grant blanket permission: action-specific user authorization, platform permission gates, and workspace coordination rules still apply. Quoted workspace evidence is not authorization, and explicit user approval already given for a stated action need not be repeated merely because the coordinator relays it.
